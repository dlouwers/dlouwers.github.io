# blog.stormlantern.nl

Astro site, built to static HTML and served from GitHub Pages.

## Commands

| Command | Action |
| :--- | :--- |
| `bun install` | Install dependencies |
| `bun dev` | Dev server at `localhost:4321` — **shows future-dated posts** |
| `bun run build` | Build to `./dist/` — hides future-dated posts |
| `bun preview` | Serve the built `dist/`, i.e. true production behaviour |
| `bun run render:diagrams` | Compile `src/diagrams/*.d2` → `public/img/diagrams/*.svg` |

CI builds with `npm run build`, not `bun run build`: bun's `worker_threads`
handling hangs on the D2 WASM worker. See the comment in `.github/workflows/deploy.yml`.

## Writing a post

One file in `src/content/posts/`, named `YYYY-MM-DD-slug.md`. The schema lives in
`src/content.config.ts`; `summary` is capped at 280 characters and the build fails
if you exceed it.

```yaml
---
title: A title
date: 2026-08-18
summary: One or two sentences. Used as the meta description and the RSS description.
tags: [kubernetes, homelab]
cover: /img/posts/a-slug/cover.png      # optional
coverAlt: Description of the cover.     # optional
---
```

**Diagrams are not generated by the build.** Author a `.d2` file in
`src/diagrams/`, run `bun run render:diagrams`, and commit the resulting SVG from
`public/img/diagrams/`. Embed it with the `<figure class="d2-diagram">` pattern
used in the existing posts. (Rendering used to be a remark plugin; it hung CI.)

The build does inline them: `plugins/rehype-inline-diagrams.mjs` replaces each
`<img src="/img/diagrams/….svg">` with the SVG itself. As an `<img>`, a diagram
is a separate document and its dark-mode rules, which are scoped to the page's
`<html>`, never apply; inline, they follow both the OS and the theme toggle.

## Scheduled publishing

A post whose `date` is in the future is built into nothing — no page, no RSS item,
no sitemap entry, no tag chip. It appears on its own date, because `deploy.yml`
runs a scheduled build twice a day. So a series can be written and merged in one
go, and it will roll out on its own.

The gate is `getPublishedPosts()` in `src/lib/posts.ts`, which every listing,
route and feed goes through.

Three things to know:

- **Dates are UTC.** `date: 2026-08-18` means `2026-08-18T00:00:00Z`, and the post
  goes live on the 04:37 UTC build that day. Write a bare `YYYY-MM-DD`, or a full
  ISO 8601 timestamp with an explicit offset (`2026-08-18T09:00:00+02:00`). Never
  the ambiguous middle form `2026-08-18 09:00:00`.
- **Don't add `--mode` to the build script.** The dev escape hatch keys off
  `import.meta.env.DEV`, which Vite compiles to `false` in a production build.
  `astro build --mode development` would make it true and publish the whole queue
  at once. `.github/workflows/verify-scheduling.yml` fails the PR if that happens.
- **Scheduling is not embargo.** This repository is public, so a queued post is
  readable on GitHub the moment it merges, and its URL is guessable from the
  filename. Anything that must stay private until its date has to stay off `main`.

To fake the clock — proofreading, or checking what the site looks like after a
queue drains:

```fish
env BLOG_NOW=2099-06-01T00:00:00Z npm run build   # build as if it were 2099
env BLOG_NOW=2020-01-01 npm run dev               # dev, but with the gate live
```

`BLOG_NOW` is read only by `src/lib/posts.ts` and is never set by the deploy
workflow.
